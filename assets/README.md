# Brand icons

**ViewCode:** the production icon comes from `viewcode-icon.svg`: a dark ambient tile (near-black
radial with a faint teal glow) holding the code-bracket and git-branch emblem from `viewcode-mark.svg`. Large exports use its gradients
and fold shading; headers and 16/32px favicons use `viewcode-mark-flat.svg`, with larger node
openings so the branch stays readable (on the dark tile its ">" takes the dark-theme slate). `viewcode-mark-monochrome.svg` supplies the single-color
Android themed and notification emblem. Run `vp run icons:export:production` to render production
mobile, desktop and web assets. iOS and apple-touch exports are full bleed and opaque; macOS
keeps an 824px tile inset 100px on a 1024px canvas. Android gets a transparent foreground inside
the adaptive safe zone, the tile and glow as a full-bleed background, and a single-color emblem for themed and notification icons.

Development and preview retain their existing assets. Their Icon Composer projects below still
contain the inherited T3 mark; do not regenerate those variants until their projects are redrawn.

Icon Composer projects are retained for development and preview artwork:

- `dev/app-icon.icon`
- `nightly/app-icon.icon`

Each project uses `text.svg` for the T3 mark and `background.svg` when the background is a vector layer. Additional layers use semantic names that describe their role and placement.

`vp run icons:export` renders production from the SVG and development/preview from Icon Composer.
The default web and marketing public icons use production; release packaging still selects its
channel-specific exports. `vp run icons:check` verifies the generated assets without changing files.

Exporting development and preview requires Icon Composer 2 or newer on macOS. The script selects the newest compatible exporter from Xcode or a standalone Icon Composer installation and pins design generation 26. Set `ICON_COMPOSER_TOOL` to the full path of `Icon Composer.app/Contents/Executables/ictool` to override automatic discovery.

## macOS exports

Production macOS artwork is generated by `icons:export:production`, and desktop packaging builds
its `.icns` from that PNG. Development and preview macOS exports still require Icon Composer's
GUI-only `macOS pre-Tahoe` preset; `icons:export` leaves those PNGs unchanged.

After changing an Icon Composer project, open it in Icon Composer and export the macOS PNG with exactly these settings:

- Platform: `macOS pre-Tahoe`
- Appearance: `Default`
- Size: `1024pt`
- Scale: `1×`

Save the development and preview exports to:

- `dev/app-icon.icon` -> `dev/blueprint-macos-1024.png`
- `nightly/app-icon.icon` -> `nightly/nightly-macos-1024.png`

The result must be a 1024×1024 PNG with the classic macOS safe area: the opaque icon body is 824×824, inset 100 pixels on every side, with only the native Icon Composer shadow extending into the surrounding transparent canvas.

To have Codex perform the native exports, paste this prompt into a task opened at the repository root:

```text
Use [@Computer](plugin://computer-use@openai-bundled) and the Icon Composer app to export the development and preview macOS app icons in this repository.

For each project below, use Platform: macOS pre-Tahoe, Appearance: Default, Size: 1024pt, and Scale: 1×, then save the PNG to the exact destination:

- assets/dev/app-icon.icon -> assets/dev/blueprint-macos-1024.png
- assets/nightly/app-icon.icon -> assets/nightly/nightly-macos-1024.png

Do not resize, composite, or otherwise post-process the exported PNGs.

Verify every result is 1024×1024 and has the classic macOS safe area: an 824×824 opaque body inset 100px on every side, with only Icon Composer's native shadow extending beyond it.
```

Do not edit the generated PNG or ICO files directly.

## Android launcher and splash artwork

Android masks the central 72dp of a 108dp adaptive canvas, and the Android 12+ splash screen masks
the central two thirds of a 288dp canvas, so the Icon Composer exports cannot be used directly:
their rounded-square silhouette gets framed again and the wordmark is cropped.
Production Android artwork comes from `viewcode-icon.svg`; development and preview artwork
comes from their Icon Composer layers. `vp run icons:export:android` renders both paths:

- `apps/mobile/assets/android-icon-foreground-prod.png`: the production transparent V
- `apps/mobile/assets/android-icon-foreground.png`: the development/preview transparent wordmark
- `apps/mobile/assets/android-icon-background-dev.png` and `-nightly.png`: full-bleed variant
  artwork (blueprint grid and annotations; night sky and clouds). Production uses
  `android-icon-background-prod.png`, the tile and glow from `viewcode-icon.svg`.
- `apps/mobile/assets/android-splash-icon-*.png`: the two layers composed into one 288dp image, so
  the splash mask reproduces the launcher icon's framing.

Rerun the export after changing a layer SVG. Production uses `android-icon-mark-prod.png` and
`android-notification-icon-prod.png` as white emblem silhouettes; development and preview keep their existing monochrome and notification assets.
